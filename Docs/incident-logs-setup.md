# Incident Logs & Postgres Database Setup

A step-by-step guide to creating and using a database in the SafePath **PostgreSQL container**, in both **development** and **production**. It uses the *Incident Report Logs* feature (the `safepath` database + `incident_reports` table) as the running example, but the same steps apply to any new database/table you need.

---

## Background: how Postgres is wired in SafePath

- The `postgres:16-trixie` container was originally **Langflow's database** (`POSTGRES_DB=langflow`, user/password `langflow`/`langflow`).
- One Postgres **instance** can host **many databases**. We add a separate **`safepath`** database for application data so it stays isolated from Langflow's managed tables.
- The backend (FastAPI) connects with **SQLAlchemy + psycopg** and auto-creates its tables on startup.
- **Postgres is not a web page.** You can *never* open it in a browser at `localhost:5432` — that port speaks the Postgres protocol, not HTTP. Use a database client: the `psql` CLI (already inside the container) or a GUI such as **DBeaver / pgAdmin / TablePlus**.

Compose files involved:

| File | Purpose | Contains Postgres? |
|------|---------|--------------------|
| `docker-compose.dev.yml` | Local development (whole stack in one file) | ✅ yes |
| `docker-compose.yml` | Production: frontend, backend, VPN, OSM | ❌ no |
| `docker-compose-langflow.yml` | Production: langflow **+ postgres** | ✅ yes |

# Part 1 — Development setup

### 1.1 Expose the Postgres port (so you can use a GUI)

By default the port is commented out and the DB is only reachable inside Docker. In `docker-compose.dev.yml`, under the `postgres` service, enable the port mapping:

```yaml
  postgres:
    image: postgres:16-trixie
    environment:
      POSTGRES_USER: langflow
      POSTGRES_PASSWORD: langflow
      POSTGRES_DB: langflow
    ports:
      - "5432:5432"
    networks:
      - langflow-net
    volumes:
      - langflow-postgres:/var/lib/postgresql/data
```

Apply it:

```bash
docker compose -f docker-compose.dev.yml up -d postgres
```

> ⚠️ Exposing `5432` is for **local development only**. Never do this in production.

### 1.2 Create the database

The Postgres image only auto-creates the database named in `POSTGRES_DB` (`langflow`), and it only runs init scripts on a **brand-new** data volume. Because the volume already exists, create the new database **manually, once**:

```bash
docker compose -f docker-compose.dev.yml exec postgres psql -U langflow -c "CREATE DATABASE safepath;"
```

Verify it exists:

```bash
docker compose -f docker-compose.dev.yml exec postgres psql -U langflow -c "\l"
```

You should see `safepath` in the list of databases.

### 1.3 Connect and inspect

**Option A — `psql` (no install, runs inside the container):**

```bash
docker exec -it senior-project-safepath-postgres-1 psql -U langflow -d safepath
```

Useful prompts once connected:

| Command | Does |
|---------|------|
| `\dt` | list tables |
| `\d incident_reports` | describe a table's columns |
| `SELECT * FROM incident_reports;` | view rows |
| `\q` | quit |

**Option B — GUI client (DBeaver / pgAdmin / TablePlus):** create a new PostgreSQL connection with:

| Field | Value |
|-------|-------|
| Host | `localhost` |
| Port | `5432` |
| Database | `safepath` |
| Username | `langflow` |
| Password | `langflow` |

### 1.4 Create a table (two ways)

**Way A — let the backend create it (recommended).** The backend defines tables as Python classes in `backend/db.py` and calls `init_db()` (`Base.metadata.create_all`) on startup, which creates any missing table automatically. Just point `SAFEPATH_DATABASE_URL` at the DB (see 1.5) and start the backend.

**Way B — create it by hand with SQL** (handy for learning/inspecting). Run in `psql` or your GUI's SQL editor:

```sql
CREATE TABLE incident_reports (
    id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    reporter_name TEXT,
    incident_type TEXT NOT NULL,
    location      TEXT NOT NULL,
    latitude      DOUBLE PRECISION,
    longitude     DOUBLE PRECISION,
    incident_date DATE NOT NULL,
    incident_time TEXT NOT NULL,
    details       TEXT NOT NULL,
    submitted_by  TEXT,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

> If you create it by hand **and** run the backend, keep the columns identical to the model in `backend/db.py`. `create_all` skips tables that already exist, so there is no conflict — but it will **not** alter a mismatched one.

### 1.5 Point the backend at the database

In the project-root `.env`:

```
SAFEPATH_DATABASE_URL=postgresql+psycopg://langflow:langflow@postgres:5432/safepath
```

- Host is **`postgres`** (the container's service name), **not** `localhost` — the backend talks to Postgres *inside* the Docker network. `localhost:5432` is only for tools running on your own machine.
- The backend reads `.env` via `env_file: .env` in the compose file.

The backend needs the DB driver in `backend/requirements.txt`:

```
sqlalchemy>=2.0,<2.1
psycopg[binary]>=3.1
```

Because dependencies changed, rebuild and restart the backend (a plain restart is **not** enough — packages install at image-build time):

```bash
docker compose -f docker-compose.dev.yml up -d --build backend
```

### 1.6 Verify end-to-end (dev)

```bash
# table exists?
docker compose -f docker-compose.dev.yml exec postgres psql -U langflow -d safepath -c "\dt"

# backend endpoints registered? open in a browser (this IS a website):
#   http://localhost:9000/docs
```

After submitting an incident report through the app, confirm the row landed:

```bash
docker exec -it senior-project-safepath-postgres-1 psql -U langflow -d safepath \
  -c "SELECT id, incident_type, location, submitted_by, created_at FROM incident_reports ORDER BY created_at DESC;"
```

# Part 2 — Production setup

Production is deployed by `deploy.sh`, which brings up **two stacks** under the same Docker project name (`senior-project-safepath`):

```sh
docker compose up -d --build                                  # docker-compose.yml     (frontend, backend, VPN, OSM)
docker compose -f docker-compose-langflow.yml up -d --build   # docker-compose-langflow.yml (langflow + postgres)
```

So in production, **Postgres lives in `docker-compose-langflow.yml`** while the **backend lives in `docker-compose.yml`**. Four things must be right.

### 2.1 Environment variable

Ensure the server's real `.env` contains (already present in `.env.production.example`):

```
SAFEPATH_DATABASE_URL=postgresql+psycopg://langflow:langflow@postgres:5432/safepath
```

Host `postgres` and port `5432` are internal Docker DNS — the same in dev and prod.

### 2.2 Network fix — the key difference from dev ⚠️

In `docker-compose.yml` the **backend is only on the `caddy` and `vpn` networks — NOT on `langflow-net`**, where Postgres lives. Without a shared network the backend cannot reach the database. Add `langflow-net` to the backend service:

```yaml
  backend:
    build: ./backend
    env_file:
      - .env
    networks:
      caddy:
        aliases:
          - backend.local
      vpn:
        ipv4_address: 172.28.0.90
      langflow-net:        # <-- ADD THIS so the backend can reach postgres
    environment:
      - ENV=production
```

`langflow-net` is already declared at the bottom of `docker-compose.yml`; both stacks share `senior-project-safepath_langflow-net` because they run under the same project name.

### 2.3 Create the database on the server (one-time)

Just like dev, the existing prod volume won't auto-run init scripts, so create the database once **on the server**:

```bash
docker compose -f docker-compose-langflow.yml exec postgres psql -U langflow -c "CREATE DATABASE safepath;"
```

The **table** is then created automatically by the backend's `init_db()` startup hook — you do not create it by hand in production.

### 2.4 Deploy

Push to the `prod` branch and run the deploy (`deploy.sh`). `docker compose up -d --build` rebuilds the backend image, installing `sqlalchemy` + `psycopg` from `requirements.txt`. On boot the startup hook creates the table in `safepath`.

### 2.5 Inspect the production database (safely)

Port `5432` is **not** exposed publicly in production (correctly commented out in `docker-compose-langflow.yml`) — keep it that way. To look at the data:

- On the server: `docker compose -f docker-compose-langflow.yml exec postgres psql -U langflow -d safepath`
- Or connect a GUI **through the WireGuard VPN** — never over a public port.

---

## Security checklist

- ✅ Expose `5432` **only** in `docker-compose.dev.yml` (local). Never in `docker-compose.yml` / `docker-compose-langflow.yml`.
- ✅ In prod, reach the DB only via `docker exec` on the server or through the VPN.
- ✅ Application writes go through the backend and are gated by Keycloak roles (`require_member` / `require_admin`).
- ✅ Change default `langflow/langflow` credentials for any real deployment.

---

## Schema changes later (migrations)

`init_db()` uses SQLAlchemy `create_all`, which only **creates missing tables** — it never alters an existing one. If you later add or rename a column you must apply it manually:

```sql
ALTER TABLE incident_reports ADD COLUMN severity TEXT;
```

For anything beyond a small project, adopt a migration tool (e.g. **Alembic**) so schema changes are versioned and repeatable across dev and prod.

## Quick reference

```bash
# Dev: create a database
docker compose -f docker-compose.dev.yml exec postgres psql -U langflow -c "CREATE DATABASE safepath;"

# Dev: open a shell on it
docker exec -it senior-project-safepath-postgres-1 psql -U langflow -d safepath

# Dev: list databases / tables
docker compose -f docker-compose.dev.yml exec postgres psql -U langflow -c "\l"
docker compose -f docker-compose.dev.yml exec postgres psql -U langflow -d safepath -c "\dt"

# Prod: create a database
docker compose -f docker-compose-langflow.yml exec postgres psql -U langflow -c "CREATE DATABASE safepath;"
```

Connection string used by the backend (dev and prod):

```
SAFEPATH_DATABASE_URL=postgresql+psycopg://langflow:langflow@postgres:5432/safepath
```
